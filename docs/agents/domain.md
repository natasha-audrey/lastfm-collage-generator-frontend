# Domain docs

Use a single-context layout: root GLOSSARY.md and docs/adr/.

Before exploring, read the glossary and ADRs relevant to the area.
If absent, proceed silently; domain-modeling creates them when
terms or decisions are resolved.

Use glossary terms in issue titles, proposals, and tests.
When a needed term is missing, reconsider the wording or raise
the gap during domain-modeling.

Explicitly flag proposals that conflict with an existing ADR
and explain why reconsidering the decision is warranted.
